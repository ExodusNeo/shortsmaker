# Photo looks, new overlays, transitions, and on-the-spot inventions: design

Date: 2026-10-18. Status: draft, waiting for the owner's review.

## In plain words (for the owner)

Each Short can get its own visual identity, chosen by the AI:

- **A photo look** (e.g. halftone print dots, copperplate engraving, risograph, toy-model tilt-shift, silent film)
  on 2-4 still scenes, the rest stay clean real pictures.
- **Two new overlays:** a *question beat* (a big on-screen question at a cliffhanger moment) and a *kinetic title*
  (a short spoken phrase whose letters drop in one by one).
- **New cuts between scenes:** hard cut, dot wipe, whip pan, light leak (plus today's fade and camera flash). The AI
  chooses the cut for every scene change; there is no fixed default.
- **Inventions:** when nothing in the library fits, the AI may invent a new look, overlay or transition for that
  Short, written as code and checked the same way as today's custom motion graphics (compile check, rule check, a
  preview it looks at and fixes, a safe fallback). A good invention is saved as a *candidate*; it joins the library
  only after the owner approves it (`library.bat`). The library grows with ideas the owner liked.

Ideas and style rules are adapted from two MIT-licensed projects: Lemo-OPUSCAR (style guides: Halftone Dossier,
Copperplate Engraving, Risograph, 1920s Silent Film; dot-wipe transition) and Showtime (question beat, kinetic type,
tilt-shift look, pacing and motion-craft notes). No code from them runs in ShortsMaker; everything is rebuilt in
Remotion. Their MIT notices go in `remotion/src/style/THIRD_PARTY.md`.

## Decisions already made (owner, 2026-10-18)

1. Overlays first; more full-screen motion graphic skins later (separate project).
2. All four: question beat, kinetic titles, photo looks, new transitions.
3. One look per Short, on 2-4 key still scenes (Lemo's rule: one style per film).
4. The AI decides everything inside six guardrails (below), including inventing new looks/overlays/transitions.
5. Inventions are saved as candidates and join the library only after the owner's OK.
6. Approach: looks, overlays and transitions all live in Remotion (one format, so the AI can learn from the presets
   when inventing). A Short that uses any of them renders with Remotion; the Python renderer is only the fallback.

## Guardrails (the only fixed rules)

1. **The hook stays clean:** scene 1 gets no look and no new overlay (it keeps the hook title).
2. **Real film clips get no look** (looks are for still pictures and AI paintings).
3. **One thing on screen per scene** (existing rule): a question beat or kinetic title replaces that scene's other
   graphic/person card.
4. **Upper limits per Short:** question beat 1, kinetic titles 2, look scenes 4, special transitions (wipe, whip,
   leak, invented) 3, inventions 1 look + 1 overlay + 1 transition.
5. **Honest facts:** a question beat must be answered later in the script; a kinetic title uses words spoken in its
   scene; both go through the fact check like other graphics.
6. **No repeating recent looks:** the channel profile keeps `recent_looks` (last 2); the director may not pick them.

Inside these, the AI may choose no look, no question, all hard cuts, etc.

## Architecture

### Remotion: `remotion/src/style/`

| Path | What |
|---|---|
| `kit.ts(x)` | Shared helpers for looks/overlays/transitions (seeded noise, palette inks, `onceCanvas` = draw a styled still once per scene with `delayRender`/`continueRender`, easing helpers) + re-exports the few toolkit pieces they may use |
| `looks/Halftone.tsx`, `Engraving.tsx`, `Riso.tsx`, `Miniature.tsx`, `Silent.tsx` | Preset looks |
| `overlays/QuestionBeat.tsx`, `KineticTitle.tsx` | Preset overlays |
| `transitions/` | `Cut`, `Fade`, `Flash` (today's two, moved here), `Wipe`, `Whip`, `Leak` |
| `library.json` | Registry: `{name, kind: look\|overlay\|transition, description, fits, file, origin: preset\|approved}` |
| `index.ts` | Generated by Python from `library.json`: name -> component maps per kind (static imports, so Remotion's bundle sees them) |
| `generated/InventedLook.tsx`, `InventedOverlay.tsx`, `InventedTransition.tsx` | Per-Short invention slots (placeholders that render nothing when unused); restored after each render like `full/generated/Custom*.tsx` |
| `candidates/<kind>-<slug>/` | Saved inventions waiting for the owner: `Component.tsx`, `meta.json`, `preview.mp4` |

**Interfaces** (one per kind, so presets and inventions are interchangeable):

- **Look:** `React.FC<{src: string; t: number; start: number; end: number; inks: Inks; seed: number}>` renders the
  scene's picture (replacing the plain `<Img>` inside `Background`, under the existing zoom/pan transform). Heavy
  pixel work (halftone dots, engraving lines) happens once per scene on a canvas (`onceCanvas`); per-frame motion
  (silent-film flicker, grain, gate weave) is a cheap layer driven by `t` and `seed`, no timers, no CSS animation.
- **Overlay:** the same props as today's cards (`{graphic, t, start, end, variant}`), drawn in the graphic slot.
- **Transition:** an object `{duration: number; render: (p: number, inks: Inks, seed: number) => {from?: CSSProperties;
  to?: CSSProperties; cover?: ReactNode}}`, where `p` runs 0..1 across the transition (centred on the cut). `Short.tsx`
  applies `from`/`to` to the outgoing/incoming scene layers and draws `cover` above both (the dot grid, the light
  leak). Durations: cut 0, fade = XFADE, flash as today, wipe 0.44, whip 0.25, leak 0.5.

`Short.tsx` changes: `Background` asks the look map for the scene's look (or none); scene changes go through the
transition map instead of the hard-coded fade/flash branch; the graphic switch gains `question`, `kinetic` and
`invented`.

### Python: planning (`make_shorts.py`)

- **Director (`direct_scripts`)** gets the library list (name, kind, description, fits) and returns, per Short,
  `look`: `{"name": "<library look>"}` or `{"invent": {"name", "brief", "fallback": "<library look>"}}` or `null`;
  per scene, `transition`: a library transition name or `"invented"` (one `invented_transition` brief per Short with
  a `fallback`); graphics may use `question` (`{"style": "question", "text"}`), `kinetic`
  (`{"style": "kinetic", "text", "trigger"}`) or `invented` (one `invented_overlay` brief per Short, used on up to 2
  scenes, with a `fallback` overlay).
- **Validation:** `clean_graphic()` learns `question`/`kinetic`/`invented`; new `clean_look()` and
  `clean_transitions()`; `limit_style()` enforces the guardrails (caps, scene 1, film scenes, recent looks). Unknown
  names fall back to `fade`/no look. A missing transition stays `fade` (today's behaviour).
- **Picture picker (`choose_images`)** gets the Short's look (name + description) and picks its 2-4 scenes
  (`look_scenes`), because it sees the actual pictures (tilt-shift only suits wide shots, etc.).
- **Fact check:** question/kinetic text is checked like other graphic text (`drop_graphic`).
- **Profile:** `recent_looks` updated after each Short (like `recent_shapes`).
- **Renderer choice:** a look, a new overlay, a non-fade/flash transition or an invention forces Remotion. The Python
  renderer draws question/kinetic as a fact box, ignores looks, and plays other transitions as fades.
- **Sound (`sfx_events`):** question = soft tick, kinetic = light ticks, whip = quiet whoosh (high-passed 220 Hz, low
  gain, owner dislikes loud whooshes); wipe/leak/cut/inventions silent.
- **edit_plan.txt:** a `LOOK:` line (name, scenes, invented or not), the cut type per scene, `QUESTION:`/`KINETIC:`
  lines like other graphics, and an `INVENTED:` section with each invention's brief and whether it passed or fell
  back.

### Python: inventions

A general `invent_component(kind, brief, short, scene, work)` built from the pieces the custom scene coder already
has (`tsc_check`, `clean_tsx_code`, the preview render, `look_and_fix`'s look-at-the-sheet loop):

1. Prompt = kind-specific rules + the kind's interface + the preset files of that kind as worked examples.
2. Lint (new `lint_style_code`: imports only `react` and `../kit`, no CSS animation/transition, no timers, no network
   or `fetch`, the exported name and props match the interface).
3. `tsc`; one repair on errors.
4. Preview: render the scene it is used on (for a transition: 1 s around its cut) small, contact sheet, the AI looks
   and fixes once (rule-checked and compiled again).
5. Pass -> written to its `generated/Invented*.tsx` slot, cached in `work/` (fix.bat reuses it), and saved as a
   candidate with `meta.json` + a few-second `preview.mp4`. Fail -> the director's `fallback` preset is used.

Cost per invention: 1-3 AI calls and about a minute of preview rendering.

### Owner approval: `library.bat` -> `make_shorts.py library`

Lists candidates (kind, name, description, which Short it came from), opens each preview, asks
approve / reject / later. Approve: moves the component into `looks|overlays|transitions/`, adds it to
`library.json` with `origin: approved`, regenerates `index.ts`, runs `tsc` (a failure undoes the move). Reject:
deletes the candidate. Claude can also do this in chat on request.

## Presets (first library)

| Name | Kind | Source idea | Rendering | Fits |
|---|---|---|---|---|
| `halftone` | look | Lemo Halftone Dossier | cream paper, 2 overprinted dot screens (dark ink + accent from the palette), +6 px misregistration | hoaxes, crime, scandal, newspapers |
| `engraving` | look | Lemo Copperplate Engraving | luminance-driven parallel hatching (+ cross-hatch in shadows), sepia ink on cream | 1500s-1800s |
| `riso` | look | Lemo Risograph | two flat spot inks by luminance bands, grain, slight misregister | 1900s-1960s, quirky |
| `miniature` | look | Showtime tilt-shift | blurred top/bottom bands, saturation/contrast up | wide or aerial shots only |
| `silent` | look | Lemo 1920s Silent Film | sepia monochrome, vignette; flicker, grain, scratches per frame | 1890s-1930s |
| `question` | overlay | Showtime question-beat | picture dims ~30 %, centred question (<= 6 words) pops and holds >= 1.2 s | open-loop moments |
| `kinetic` | overlay | Showtime kinetic-type, Lemo per-glyph pop | letters drop 30-100 px and squash in, 0.05 s stagger, accent offset shadow | key spoken phrases |
| `cut` | transition | Showtime pacing | hard cut | default energy |
| `fade`, `flash` | transition | existing | unchanged | time jumps; impact |
| `wipe` | transition | Lemo dot wipe | dot grid in the look's ink grows over the frame and shrinks (0.44 s), scene switches while covered | halftone, riso |
| `whip` | transition | editing convention | fast lateral pan with motion blur (0.25 s) | action beats |
| `leak` | transition | film convention | warm light-leak burn (0.5 s) | silent, engraving, nostalgia |

## Testing

- **Python (`tests/test_full_scenes.py` or a new `tests/test_style.py`, plain asserts, no AI usage):** clean_graphic
  for question/kinetic (spoken-word trigger, length, question mark), clean_look/clean_transitions (unknown names,
  scene 1, film scenes, caps, recent_looks), renderer choice forced to Remotion, the invention path with a fake
  `ask_ai` (pass -> slot + candidate written; lint/tsc failure -> fallback), library approve/reject (files moved,
  `library.json` and `index.ts` regenerated, failure rolls back).
- **TypeScript:** `npx tsc -p remotion`; the existing `tests/run_ts_tests.py` gains a test that every `library.json`
  entry has a component in `index.ts`.
- **Owner gate 1 (before any planning code):** `test_renders/STYLE_PREVIEW.mp4`: each preset look on 2-3 real photos
  from past Shorts, both overlays, every transition. The owner approves or rejects each one.
- **Owner gate 2:** one real Short with the planner choosing (and possibly inventing), reviewed as usual.

## Build order

1. `style/` folder, interfaces, `kit`, preset looks/overlays/transitions, `Short.tsx` plumbing, `library.json` +
   generated `index.ts`, preview video -> **owner gate 1**.
2. Planning: director + picker prompts, validation and guardrails, renderer choice, sounds, edit_plan, profile.
3. Inventions: `invent_component`, slots, candidates, `library.bat`.
4. One real Short -> **owner gate 2**; HANDOFF.md updated.

## Risks

- **Render time:** canvas looks are drawn once per scene, so the cost should be small; measured on the preview.
- **AI invention quality:** guarded by lint, compile, the preview look-and-fix and a preset fallback; inventions reach
  the library only with the owner's OK.
- **Pixel access:** canvas reads of the scene picture need same-origin images; the pictures are served by Remotion
  from `public/job`, which is same-origin. Checked in step 1.
- **Overuse:** the upper limits and "one thing on screen" stop clutter; the AI is told none is a fine answer.

## Out of scope

More full-screen motion-graphic skins (next project); Lemo/Showtime's own renderers, voices and music; looks on real
film clips; the gaming channel's cartoon/pixel styles (possible later as library additions).
